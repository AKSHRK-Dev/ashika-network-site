Why it stops when you run it on your PC

A Discord bot is not finished once it is written. Your program has to be running at the very moment someone types a command. In other words, it has to stay on 24 hours a day.

On your own PC, it stops when:

  • you close the lid, the PC goes to sleep, or you shut it down
  • a Windows update restarts it during the night
  • the connection drops or the router restarts
  • it crashed with an error while you were asleep

None of these can be avoided by just being careful. A PC is a machine for people to use, not one built to run without stopping. Electricity adds up too: leaving a laptop on costs a few hundred to about a thousand yen a month in Japan. A ¥30-a-month server ends up cheaper.

Many people wonder whether a free cloud tier would do. Free tiers usually come with limits: they stop after a period without traffic, or cap your running hours each month. That does not suit a Discord bot, which needs to stay on.

A note on music bots

Bots that play audio use more CPU and memory than other bots, because the audio is encoded all the time. For one or two servers, Plus is a safe choice; as more people use it, look at Pro or above.

With discord.py (Python)

Bots written in Python can be uploaded as they are. Put a requirements.txt next to your code and the libraries you need are installed together.

discord.py
python-dotenv

Do not write the token into your code; read it from an environment variable. That way you will not leak it by accident when you show someone your source.

import os
import discord

client = discord.Client(intents=discord.Intents.default())

@client.event
async def on_ready():
    print(f"Connected as {client.user}")

client.run(os.environ["DISCORD_TOKEN"])

About intents. Bots that read message content, or want to know when members join and leave, will not work unless you turn on the "privileged intents" on the Discord developer portal. If it worked on your PC but not on the server, this is often why.

With discord.js (Node.js)

Node.js works the same way. Put your package.json in place and the packages you need are installed.

const { Client, GatewayIntentBits } = require("discord.js");

const client = new Client({ intents: [GatewayIntentBits.Guilds] });

client.once("ready", () => {
  console.log(`Connected as ${client.user.tag}`);
});

client.login(process.env.DISCORD_TOKEN);

You set the start command in the panel. Enter the same thing you always type on your PC, such as node index.js.

If it crashes, it starts again by itself

However carefully you write it, a program sometimes crashes: a temporary problem on Discord's side, input you did not expect, running out of memory.

On ASHIKA Network, crashes are detected and the program is restarted automatically. If it falls over at night, it is running again by morning. You do not have to watch it.

The cause of the crash is still there, though. You can follow the logs in your browser, so if it keeps crashing the same way, take a look and fix it.

Common stumbling blocks

It works on my PC but not on the server

It is almost always one of these three:

  • A library is missing: upload requirements.txt or package.json together with your code.
  • An environment variable is missing: set the token and similar values in the panel.
  • Privileged intents are off: turn them on in the Discord developer portal.

It runs for a while, then crashes

Suspect a lack of memory. If you keep data you no longer use, memory use slowly grows until it hits the limit. Either move up one plan or look over your code.

My token stopped working

If a token is published by accident, Discord disables it automatically. A common case is a token left in code pushed to GitHub. Issue a new one and read it from an environment variable instead.
